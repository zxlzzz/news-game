# Husky 动作库

新增 **46 条片段**，其中 **11 条循环**，总时长 **129.6 秒**，全部 30 fps。数量包括左右版本、进入/退出过渡及保持片段，不代表 46 种完全不同的行为。

## 直接看与使用

- 打开 [review.html](review.html)，点名称播放每条动画；左侧是侧面，右侧是游戏角度。无需联网。
- [husky_motion_library.glb](husky_motion_library.glb)：原来的 Husky 网格、41 骨、蒙皮和 12 个 Quaternius 动作全部保留，另外附加 46 个 `NG_` 前缀动作，**共 58 个动作**。
- [clip_manifest.json](clip_manifest.json)：中文名称、时长、帧数、循环标记、前后姿势状态及预览路径。
- `overview_01.png` 至 `overview_06.png`：全库按六个时刻排列的游戏角度检查图；`sheets/` 是逐条侧面 + 游戏角度分解图，`previews/` 是逐条 GIF。

这是当前 Husky 骨架的动画资产，不是运行时行为代码。没有接进游戏，没有改 `godot/`，2026-09-28 已按用户授权，将对应模型更新为四肢和爪子加厚版本，全部动作重新适配落脚。ShibaInu / Cat 的骨数及比例不同，已分别交付各自的动作库，不能混用骨名。

2026-09-28 坐姿修正：两后爪向前收 8 cm、分别向外移 4 cm；跗关节配合转向 25°。所有坐姿保持、递爪、坐下、起身、坐趴互转同步使用这个后腿布局，抬起的后爪沿可达范围移动，未拉长骨头。

## 覆盖内容

站立呼吸与警觉、看左右和上下、左右歪头、单耳/双耳抖动、慢/快摇尾、谨慎收尾、嗅空气、嗅地进入/循环/退出、全身抖毛与短甩头、左右前爪抬起/坐姿递爪、左右后腿标记、坐下/保持/张望/摇尾/起身、趴下/保持/起身、坐趴互转、入睡/睡眠/醒来、邀玩鞠躬、前肢伸展、短暂受惊、翻到侧躺/侧躺呼吸/翻回趴姿。

左右挠耳两条做了试片但**没有收入 GLB**：此模型的后爪不能自然接触耳根，硬追目标会超出腿链可达范围。记录在 `motion_specs.json` 的 `deferred`，未拿错误动作凑数。

## 制作方法

- 参考项目现有 `godot/npc/animal-actions.json`、`animal_actions.gd` 的动作类别和接触原则，以及已交的 Husky 静态变形测试；按当前实际骨长重新制作，没有把旧线条狗的坐标直接套进网格。
- 读取已转换 Husky GLB。原始节点、网格、材质、蒙皮、逆绑定矩阵及原 12 个动作的数据保持原样；只在 GLB 后面追加新动画访问器与缓冲区。独立检查比较了这些原始数据，确认没有改形或重刷权重。
- 在离线制作阶段，以刚性骨变换和解析腿链解算安排姿势，保持骨长。落脚用变形后的爪底实际顶点反馈修正，转为逐帧平移/四元数关键帧；没有导出 IK 或其他约束。
- 坐下时前爪向后补一步；坐趴互转时，抬起的前爪沿骨链可达区域外缘移动，避免穿过上下臂长度差造成的不可达区。落地阶段不靠伸长骨头去够目标。
- 循环最后一帧重复第一帧；不同姿势间有独立进出片段。模型尺寸、外观和骨架沿用前轮交付。

## 实际检查结果

`verify_motions.py` 从最终 GLB 独立重算层级变换和蒙皮，不依赖制作时的骨链解算器。除了全部 30 fps 烘焙键，还检查了键之间的半帧插值，即以 60 fps 检查实际变形。

- **46 条全部通过**：帧数/采样、有限数值、四元数、骨架单位变换、贴地、站定爪误差、抬爪轨迹、循环首尾和明显逐帧跳变检查。
- 最大站定爪误差（含半帧）：**0.077 mm**。
- 最低顶点越过地面最大值（含半帧）：**0.154 mm**，小于 2 mm 检查容差。
- 11 条循环的首尾顶点位置一致；16 对可直接相接的姿势边界已检查，最大差 **0.145 mm**。
- 抬起的爪也检查是否跟随设定路径，不能靠把它标记成“非着地”来隐藏不可达目标。侧翻阶段不要求爪固定在地面。
- 完整输出见 `check.txt`，数值见 `verify_report.json`；制作阶段诊断见 `motion_report.json`，每帧落脚计划见 `contact_plan.npz`。
- 原模型检查器输出在 `model_check.txt`；仍然只有明确接受的 `animal_ink` 色槽名 FAIL。

视觉复核看了全部片段的侧面和游戏角度分解图，重点复核坐趴进出、嗅地、侧翻、递爪和抬后腿。**没有做全库三角面自相交证明，也没有在 Godot 实机中验收**；数学通过不等于所有姿势都已经达到最终美术质量。

## 接入注意

1. 只挑 `NG_` 前缀就是本轮新增动作；`Walk`、`Gallop` 等原动作仍保留，不计入新增数量。
2. glTF 没有标准循环开关。按 `clip_manifest.json` 的 `loop` 设置 Godot 动画循环；GLB `extras.loop` 只是提示，不能假定导入器会自动处理。
3. 状态链示例：`NG_Sit_Down → NG_Sit_Idle → NG_Sit_Get_Up`；`NG_Lie_Down → NG_Sleep_Enter → NG_Sleep_Breathe → NG_Sleep_Wake → NG_Lie_Get_Up`；`NG_Sniff_Ground_Enter → NG_Sniff_Ground_Loop → NG_Sniff_Ground_Exit`。
4. 侧躺从趴姿进入，返回也是趴姿，再接 `NG_Lie_Get_Up`。不要把侧躺保持直接硬切到站立。
5. 站姿警觉、摇尾等可按约 0.2 秒混合进入。与实时程序摆骨头的控制权交接由游戏端决定；不要同时让程序和整身动画覆盖同一根骨头。
6. 全部是原地片段。`Body` 可作上下起伏和侧翻所需的垂直位移，不含前进路径；水平移动、地形适应、动作选择都由游戏端处理。

## 已知限制

- 原 Husky 的低面数、短上臂与粗胸仍会让大幅折叠呈现块状轮廓，坐趴和髋部抬起最明显。本轮按新授权加厚了四肢外形；拓扑与权重仍保持不变。
- 侧躺是原地转到一侧休息，不能当作连续翻滚动作。受惊没有跳离地面。抖毛没有软组织或毛发物理。
- “入睡”只有身体和头的姿势变化，没有眼皮动画；没有新增嘴部骨头，因此没有拿无张嘴的动作冒充完整吠叫。
- 呼吸、耳动是细动作，在游戏二三十像素高度可能不明显；保留它们作为近景或叠加使用的素材。
- GIF 为方便查看会重复播放。单次/过渡片段末尾停顿后重置，那个重置不是 GLB 中的动画。

## 重跑

无需原始 .blend，只依赖相邻模型交付中的 `animal_husky.glb` 与 `verify_husky.py`。Blender 5.2.2 自带 numpy；Python 预览拼图需要 Pillow，独立验证需要 numpy。所有参数在 `motion_specs.json`。

```powershell
& 'D:/steam/steamapps/common/Blender/blender.exe' --background --python delivery/animals/husky_motion_library/build_motions.py -- --preview
python delivery/animals/husky_motion_library/make_previews.py
python delivery/animals/husky_motion_library/verify_motions.py
```

不带 `--preview` 时仅制作动作、GLB 与检查用数据；`--out` 可指定输出目录。`frames/` 是拼 GIF 前的临时逐帧 PNG，可在拼图后删除。本次已清理临时帧，只留可播放预览和复核图。重跑一致性结果见 `reproducibility.txt`。
