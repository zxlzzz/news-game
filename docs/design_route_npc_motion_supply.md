# NPC 动作素材供给 — 设计路线

2026-09-16 讨论结论记录。本文只描述素材从哪来、怎么进管线，不含实现细节。

当前交付是 `assets/animations/npz/<name>/motion.npz` 与 `meta.json`。素材保留源关节，显示造型在绘制时映射；不预先烘焙成最终火柴人坐标。

关联：
- `design_route_npc_behavior.md` — 行为系统，决定播哪个 json
- 09-06 路线结论 — 三渲二为什么否、关节为什么升三维、文字生成怎么进来的

---

## 0. 这个文档解决的问题

**大量动作 json 从哪来，而且不靠逐个手摆关节。**

行为系统的最小单元是一个动作 json，动作数量不可妥协。本文只管供给。

不管：播哪个 json（行为系统）；火柴人画成线条还是体积（§6）；引擎。

---

## 1. 前提（09-06 定下的方向）

- NPZ 保留 77 个源关节每帧的**三维坐标**；映射使用其中 16 个源关节，输出点和连线以 `docs/design-plans/npc-skeleton-mapping.md` 为准。
- 朝向不做成资产：绘制时绕竖轴转到当前朝向，再投影。一条 json 覆盖所有朝向。
- 当前造型已定为实心圆头、等宽圆头线的简洁火柴人，不画肩/胯横线和影子。

---

## 2. 管线

```
一句描述（+ 可选约束）
  → Kimodo 生成：77 个关节每帧的三维坐标 + 左右脚跟脚尖触地标记
  → 保留源 motion.npz + meta.json
  → 绘制时读取所需 16 个源关节
  → 按 npc-skeleton-mapping.md 的比例、两骨 IK、头部校正与举臂外展生成绘制点
  → 朝向/相机投影与深度排序绘制
```

- 映射不是直接挑点：下半身及位移按腿长缩放，IK 重建膝盖；肩向量分配进两段手臂，头部去除站姿前倾，举臂平滑外展。具体规则与参数见 `docs/design-plans/npc-skeleton-mapping.md`。
- 共用纯映射函数与独立参数 JSON 是已定实现要求；源资源不写回映射坐标。仓库预览已提取共用模块，游戏集成仍未完成。
- 每条描述生成上限 10 秒，对一个动作 json 够用。更长的拆成几段，Kimodo 自带多段衔接。

---

## 3. 三类动作各从哪来

| 类别 | 例子 | 来源 | 状态 |
|---|---|---|---|
| 单人 | 挠头、刷手机、扔垃圾、老人走 | 直接生成；风格写进描述（"一个老人……"） | 在官方覆盖范围内：走跑、手势、日常活动、常见物件交互、疲惫/醉酒/年老等风格 |
| 贴合物件 | 坐长椅、开门、在摊位前挑东西 | 生成时给手/脚末端位置约束，剩下的误差用端点 IK 修 | 官方报告末端位置误差约 3.6cm，未实测 |
| 双人接触 | 握手、搀扶、背人、搂肩 | 先生成 A；再生成 B，把 B 的手在接触那几帧约束到 A 身上 | **推断，未验证。** 单向：A 不会对 B 做出反应 |

双人的备选是专门的双人生成模型或数据集（见附录）。现在能直接跑的少，数据集多为科研限定。

---

## 4. 生成之后怎么改

生成出来允许改，不要求一次生成对。改有两层，都不是逐帧摆关节：

1. **改约束重新生成**（主要改法）：在 Kimodo 界面的时间轴上挪几个关键帧的手脚落点或全身姿势，模型把中间补齐。
2. **映射后的单动作微调**：在已定造型规则基础上处理具体动作；微调格式尚未定，不把旧的“四肢端点每帧约 12 个数”当作当前资源格式。

---

## 5. 和行为系统的接口

**素材里的世界坐标不直接当作 NPC 的位置。** 位置接续由播放端负责，见 `design_route_npc_behavior.md` §5：切换时以 NPC 当前所在位置接续下一条片段，消费片段内根节点的相对位移，不直接套用素材的绝对坐标。移动片段与导航的协调属于播放/移动实现。

行为可在任意帧被替换，不保证播完。

**素材首尾规则（2026-09-22 定）：**

1. **新生成的素材，每段都要有入口姿势（首帧）和出口姿势（末帧）。**
   - 反复播放的动作（走路、站立这类循环）入口和出口是同一个姿势：生成时用 Kimodo 关键帧约束，把末帧钉成首帧。
   - 从一种状态换到另一种状态的转换动作（坐下、走路→站立）要等它前后两段循环都生成好了才能生成：首帧钉成前一段循环的首帧（循环首尾相同，这也就是它的末帧），末帧钉成后一段循环的首帧。
2. **这条规则只管素材怎么生成，不改播放。** 切换仍然可以发生在任意帧；中途打断造成的姿势跳变，等实际画面接受不了再补过渡。不要求等循环播完再切换，因为那样 NPC 的反应最多会晚一整遍循环（phone_walk 一遍 4 秒）。
3. **播放时，一段接下一段，如果上一段的末帧和下一段的首帧是同一个姿势，这两帧只播一帧**，免得停顿一帧。循环播放就是"下一段是它自己"的情况。（播放端目前还没做这一步。）
4. **已有的 63 条不按这条规则重新生成。** 其中当作循环用的素材，首尾之差在导出时修正：把差值线性平摊到整段，根节点的水平位置不动；修正量超过 15 cm，或首尾着地的脚不同，导出就报错停下，不修。哪些素材是循环，从记录每段入口/出口姿势的单独 json 里读，不写进素材的 meta.json。**这一条未实现**，目前只是定下的做法，导出脚本和播放端都还没改。

当前设计不要求切换前先播退出段。姿势过渡是否需要补，等游戏中的实际效果再决定。

## 7. 许可与来源记录

- 现阶段定位：科研 / 游戏雏形，非商用。

- 提议（未拍板）：每条 json 记一个来源字段，写明由哪个模型或数据集生成。将来要发布时，能按来源把受限的整批剔除。
