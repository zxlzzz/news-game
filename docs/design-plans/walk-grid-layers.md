可走区域分层：桥上桥下、台阶
2026年9月26日 · @Hsinlung
要解决什么
可走区域要同时做到两样：A 不同地面走起来有偏好（godot/core/walk_costs.json：人行道 1、斑马线 1.2、草地 4）；B 桥上桥下、台阶上下分得开。
现在的 godot/core/walk_grid.gd 有 A 没 B。它每格只记一个脚下，路径点高度写死 0；离地 0.3 m 以上的东西一律当障碍，所以台阶和桥都是墙。Godot 自带寻路有 B 没 A，原因见 walk_grid.gd 开头的注释。
改法：每格记下竖着看有几个能站人的面，按下面的规则把相邻格的面连起来，交给 AStar3D 找路。每个面是一个点，点上带这个面的偏好；偏好表不变。

找路时间看的是路有多远，不是地图多大。Hsinlung 定了后面大部分寻路只走短路，所以这次不做远路优化。
每格记哪些面
每格竖着看，把所有能站人的面都记下来：高度和地面种类。
• 面从哪来：场景里所有模型朝上的面，包括 GroundStrip 生成的地面带。朝上沿用现在的判据（法线 y ≥ 0.7），法线 y 在 ±0.7 之间的算竖直面。取格子中心处的高度。
• 地面种类：面的材质映射到的色槽，沿用现在 paving 用的映射。映射不到色槽就报错退出；现在只对 paving 查，改成对所有参与的面查。
• 走不了的面也记：水、屋顶、长椅座面这些，这个模式没有代价，就不进找路，但要留在网格里。以后"桥边、下面是水"要从这里推。
• 被盖住的面去掉：同一格中心，一个面正上方 clearanceHeight（现在 1.8 m）以内还有任何不竖直的面，这个面就不能站。于是 plaza 板下 2 cm 的地面带、长椅下的地、桥墩里面的地都去掉；桥下的地离桥底 2.7 m，保留。
• marking 组：它的面既不算能站的面，也不挡东西。
• crosswalk 组：照现在的规则切地面带，它自己的面不参与。
• paving 组：不再决定"铺地"，它的面按上面的通用规则算。组名的意思改成"这个物件的面是给人走的，走不到要报错"，见第 5 节。
哪些面之间走得过去
桥上桥下分开、台阶能上，全靠这一节：相邻两格的面要同时满足下面几条才连通。
1. 高差不超过一级台阶。台阶高每个模式一个，放进 npc/crowd-params.json 的 grid；初始值 walk 0.25 m、ride 0.05 m（自行车不上台阶、不上路沿），Hsinlung 调。桥下的地和旁边格子的桥面差 3 m，连不上；台阶一级 0.15 m，一级接一级连上。
2. 中间没有竖直面挡着。一个竖直面如果和"较低那个面往上，从一级台阶高到 clearanceHeight"这段高度有重叠，它经过的地方就不能穿过。1 m 高的栏杆挡；台阶立面只有一级高，不挡；桥面边缘在桥下的地上方 2.7–3 m，不挡桥下的人。薄于一格的栏杆、墙也必须挡住，不能只看格子中心。
3. 斜着走沿用现在的规矩：两边的直角邻格都通才能斜着过去。
4. 离断开的地方留距离。一个面在 clearance（现在 0.3 m）以内有断开的地方，这个面就不用；断开指那个方向没有面、高差超过一级台阶、或被竖直面挡住。它代替现在"按物件包围盒往外扩 clearance"的做法。连着的台阶、路沿、草地不算断开；机动车道这种面在、只是这个模式没代价的，也不算断开，所以人照旧能贴着路边走。
往下跳的连接这次不加，见第 6 节。
找路和拉直
每个模式一个 AStar3D，路径点带上所站那个面的高度。
• 点和连线：这个模式下有代价的每个面是一个点，点的偏好 = 代价（斑马线切出来的格子照旧用 crosswalk 代价）；连线按第 3 节。
• 吸附到面上（现在的 snap）：给一个位置，找离它最近的可用面，要连高度一起比。站在桥上的人不能被吸到桥下。
• 拉直：保留现在的条件（直线经过的格子都可用、不比两端贵），再加一条：只在高度相同的面之间拉直，经过的每一格都要有一个同高度、和上一格连得上的面。高度变了的格子留作路径点，所以台阶上每一级都是一个点；桥上的一段也不会被拉成从桥下穿过去的直线。
• 输出：plan 返回的点带真实高度，不再写死 0。
跟着要改的地方
• GroundStrip 不再必需：网格范围取所有能站的面的水平范围，露台那种整块模型的场景也能用。没有 GroundStrip 却放了 crosswalk 物件就报错退出，因为斑马线规则靠地面带。
• 出口（exits）：还是网格左右两端碰到的可用面，walk 照旧只取代价 ≤ exitMaxCost 的；出口点带高度。
• 从入口能走到哪（_flood_walk）：沿第 3 节的连线推，不再按格子上下左右。random_point 只在推得到的面里挑。
• 走不到就报错（unreachable_areas 和 crowd.gd 里的检查）：只查地面带和 paving 组物件的面。其他物件顶上的面（屋顶、花坛顶）走不到不报错。桥、台阶这类给人走的模型要放进 paving 组。
• 写死地面高度 0 的地方改成用路径点或网格给的高度。已知的有 npc/crowd.gd 出口点的 0.0、npc/procedural_dog.gd 落脚的 foot.point.y = 0、npc/leash.gd 的 groundClearance 以 0 为地面；其余自己 grep 找全。狗的脚要落在它当前所站的面上，网格要能回答"这个位置、这个高度附近的面有多高"。
• tools/walk_grid_image.gd 要还能跑；一格有多个面时，按从下往上第几个面分别出图。
• 文档：walk_grid.gd 开头注释、docs/scene_spec.md §3 可走区域那一行、godot/README.md 里讲可走区域的地方，和代码同一个 commit 改。
这次不做
• 往下跳的连接、桥上跳河：跳河是人想跳，属于行为那边；网格只保证"桥边、下面是水"推得出来。
• 台阶上的脚步动画：人的身体会顺着路径点的高度上下，脚不对齐台阶。
• 远路优化（粗地图）。
• 鸽子、飞行。
• 不改 scenes/street_demo；它照旧能建出网格、不报错即可。
验收
新增检查 godot --headless --path . -s res://tools/check_walk_grid.gd → 输出 WALK_GRID_OK，写进 CLAUDE.md「检查」节；原有的 MAPPING_OK、LOCOMOTION_OK 照旧通过。
检查用一个单独的测试场景（新文件夹，不碰 street_demo），模型可以用 Godot 自带方块拼，材质名按色槽取。场景里至少有：一座跨过下层步道的桥，上桥的台阶（一级 0.15 m），一段路沿，一个 0.5 m 高的花坛，一道厚 0.08 m、高 1 m 的栏杆，一张长椅，一块 plaza 板。检查要断言：
1. 桥下步道从一头走到另一头，所有路径点高度都是 0，没上桥。
2. 从地面到桥面的路径走台阶，相邻路径点高差都不超过 0.25 m。
3. 栏杆两边之间的路径绕开栏杆，没有穿过去。
4. 长椅下、花坛里的格子不可用；plaza 板面可用，板下的地面带不在。
5. ride 模式到不了台阶和桥面。
6. 桥面上的一个位置吸附后仍在桥面上。
7. street_demo 能建出网格，不报错。
grep 可验：
• grep -n AStarGrid2D godot/core/walk_grid.gd 没有结果。
• grep -n maxStep godot/npc/crowd-params.json 有结果（台阶高就叫 grid.maxStep，按模式分：{"walk": 0.25, "ride": 0.05}）。
