# 双人互动设计 v1.0

> 冻结决策记录。日期：2026-07-25。

## 背景

现有 4 个双人 clip（`give_item` / `handshake` / `point_at` / `push`，各 1 帧）为早期预留，
从未投入使用。原因不是姿势画得不好，而是**运行时与编辑器各自假设了一套间距，两套对不上**。

运行时一侧：

- `SocialLayer.js:156` 的配对条件为 `dx < 70 && dx > 14 && dy < 24`。
  两人水平距离在 14~70px 之间任意取值，而双人姿势的关节坐标是写死的
  → 两只手最多错开 56px（人物总高 144px）。
- `dy < 24` 允许两人处于不同 y 带，深度不同则 `scale` 不同
  → 即使 dx 正确，两人一大一小，接触点仍对不上。
- 站位间距不存在于任何数据中：`TalkActivity` 只调 `_faceEachOther()` 设朝向，
  两人就地在原位触发。

编辑器一侧：

- `stick-puppet` 的 `_enterDuetMode` 硬写 `offset = ±80`，即作画时两人固定相距 160px。
- `exportJSON` 的 duet 分支不导出 offset。拖动对齐两只手、导出、再载入，
  offset 回到 ±80，对齐结果丢失。

即：**编辑器按 160px 作画，运行时按 14~70px 摆位，且两者都没有把间距写进数据。**
因此本设计的核心不是重画姿势，而是让站位间距成为 clip 数据的一部分（见 D2），
由编辑器写出、运行时读入。

## 决策

### D1 — 一个 clip 装多个角色（维持现状）

判据：
- **几何耦合**（必须接触：握手、牵手、递物、推搡）→ 一个文件，角色在内部。
- **仅时间耦合**（追逐、一人指另一人看）→ 两个独立 clip + 行为层协调。

理由：需要校验的是"两个接触关节是否重合"，这是相对关系。
两半分居两个文件时无法在单一位置校验，且可各自漂移而无人报错。

### D2 — `participants` 增加站位声明

形状照抄 `propDefaults.js` 中 `smartDef.slots` 的既有写法（`role` + `dx` / `dy`），
不发明新形状。第一个角色为坐标原点（dx=0, dy=0），其余角色相对它声明。

站位声明是 clip 的一部分，不是行为层的常量。

### D3 — 角色名使用语义名

禁止 `a` / `b`。行为层需要决定谁演哪个角色，`a`/`b` 不提供任何依据。
`human_pet_dog.json` 已在使用语义角色名（`human` / `dog`），沿用该惯例。

### D4 — 接触类要求两人同深度

配对前置条件中 dy 容差收紧（骨架单位，见文末「单位约定」）。不同 y 带的两人不得进入接触类互动。

### D5 — 互动表脱离 TalkActivity

`SUB_EVENTS` 目前硬写在 `TalkActivity.js` 内，只有"两人正在聊天"这一场合能触发。
牵手发生在走路中而非聊天中，按现有结构必须改 `TalkActivity` 才能新增
——违反「拆分只按层次、禁按应用场合」。

改为独立数据表，一个互动一行，声明：姿势 clip、伸手/保持/收回时长、
要求间距、标签、是瞬时还是持续。场合无关，任何场合可消费。

本次不改 Activity 层（多人协调）本身，仅搬表。

### D6 — 先走到间距再触发

配对不再"就地触发"。判定通过后两人先移动到声明间距，到位后互动才开始。

### D7 — 校验

`validate.mjs` 增加接触检查：声明了接触关节的 clip，在声明间距下
两角色的指定关节距离必须小于阈值（骨架单位，见文末「单位约定」）。

## 明确不做

- **动作幅度按两人距离缩放。** 间距已由 D2 固定，变化不存在；
  且需要角度空间/IK 前置，并在裁决表外引入距离比较。
  需要动作变化时使用既有的 `variant_of` + `amp`。
- **不改 Activity 层的多人协调机制。**

## 顺序约束

编辑器参照层（见 `editor-reference-layer-v1.md`）必须先落地。
在编辑器无法显示对手方灰影的情况下，无法画出接触正确的双人姿势
——现有 4 个双人 clip 就是这么产生的。

## 单位约定（U-1，2026-08-05 补充）

C-2 的所有接触量——配对行走目标距离（D6 的"声明间距"）、接触判定阈值
（D4 的 dy 容差、D7 的关节距离校验）、reach 距离——一律定义在骨架单位，
消费时乘 `npc.scale`。世界像素不是接触量的合法单位：同一个像素值在近侧
（scale≈0.262）与远侧的渲染尺寸相差数倍，只在一个深度成立，换了深度就错。

依据：`TalkActivity.js` 曾把 `cfg.designGap`（PoseCacheBuilder 输出，编辑器
坐标即骨架单位）直接当世界像素用，近侧 scale≈0.262 时 70 骨架单位应渲染成
18px，实际站开了 70px，约 4 倍，且错的倍数随 y 变——已在 U-1 修正（消费时
乘 a/b 两者 scale 的平均）。D4/D7 原先写的"≤2px"是同一类错误的估计值，
只在编辑器画图时假设的那一个深度成立，已删除；两处落地时改为在骨架单位下
声明阈值，具体数值待 D-2/D-7 实际实现时校准，不在本次预先假定。
