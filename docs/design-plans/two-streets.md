# 两条街大场景：要求（2026-09-26）

状态（2026-09-27）：已搭好，`godot/scenes/two_streets/`（实现说明见 `godot/README.md`"两条街"一节）。镜头、网格缓存、道路合并描线、斑马线切道路模块、四周背景都已做；楼用第六批的居民区和商业楼，路人由行为表驱动；帧率约 60。

## 1. 镜头

镜头用**透视**（近大远小，2026-09-28 Hsinlung 定；原来是正交，切换只改 `core/camera-params.json` 的 `projection`，见末尾）。操作（Hsinlung 定）：

| 操作 | 做什么 |
|---|---|
| WASD / 方向键 | 平移。方向按屏幕：W 是屏幕上方在地面上的方向，随转角变 |
| 按住左键拖 | 平移，拖住的地面点跟着鼠标走 |
| 按住中键拖 | 转视角：左右拖 = 水平自由转 360°；上下拖 = 俯仰，连续可调 |
| 滚轮 | 缩放，以鼠标下的地面点为中心 |
| 左键 / 右键单击 | **预留给玩法**（点人、拍照）。左键按下后移动超过几像素才算拖动，否则算单击，镜头不动 |

- 镜头绕一个"注视点"转：注视点在地面上，镜头在它斜上方，离开的方向由水平转角和俯仰角决定。
- 俯仰范围有上下限（太平会看到地平线外的空白，太陡就成正俯视）；缩放有最近、最远两档；注视点不能移出场景范围。具体数值放 JSON，先按下面的起始值试，看画面再调：俯仰 20°–85°，默认沿用现在 demo 的约 38°；画面高度 8–150 米，默认 42 米。
- 命令行截图参数照旧能用（定位置、转角、俯仰、画面大小、正俯视）。
- **自由转带来的要求**：楼的四面都会被看到。只做正面的"后排楼"（`building_back_row_*`）放进这个场景时，背面会露馅；场景边缘外面也会被看到。所以：
  - 第六批还没交的 `building_back_row_residential_a/_b` 改成四面都做（背面简单即可），已改清单。已入库的 4 种后排楼只摆在背面看不到的位置，或者看效果再决定要不要返工。
  - 地面铺到场景外一圈，注视点限制在场景范围内，边缘外只露空地。

## 2. 布局

街道沿 X。从 -Z 到 +Z：

| 区域 | 进深（Z） | 内容 |
|---|---|---|
| 商业侧 | 约 50 米 | 商场、写字楼、酒店、超市、电影院、停车楼、百货楼，楼前广场 |
| 街 B | 20 米 | 完整横截面 |
| 中间街区 | 约 60 米 | **两排楼背靠背，各自朝向自己那条街**（现有住宅楼进深 9–12 米，两排之间剩约 35 米放院子、车棚、垃圾站）；住宅为主（板楼、连排、转角楼、里侧住宅），小区围墙和大门、车棚、垃圾站、院子铺地、晾衣架；临街有小店 |
| 街 A | 20 米 | 完整横截面 |
| 公园侧 | 约 40 米 | 公园和各种建筑（沿用现有 demo 的公园、临街楼） |

- 两条街各约 200 米长，两端开口通到场景边缘，人从那里进出。
- 连通（Hsinlung 定）：中间街区一端有**一条横路**连起两条街（两头各一个丁字路口）；街区中间再穿**两条小巷**（两头用 `road_alley_entry` 接街，中间 `alley`；现在在 x = −35、25），人能从一条街走到另一条。
- 路面全用道路模块拼；公园、院子、广场用各自的地面或铺地模型。场景边外铺一圈普通地面。
- 具体摆位先出一张俯视草图给 Hsinlung 看，定了再摆。

## 3. 技术上要先做的

1. **可走网格缓存**：做法见 `godot/README.md` 街道 demo 一节的"待做"。场景面积约是现在 demo 的 5 倍，不缓存每次开要等十几秒。
2. **道路合并描线**：同上 README 的"待做"。道路 glb 导入要关网格压缩。
3. **类型文件**：第五、六批模型还没建类型（`types/`），摆进场景时逐个建。
4. **性能**：人数按面积比例，先按现在 demo 的密度；目标是这台机器 1080p 60 帧。做完先量帧率，再决定描线、阴影、人数要不要降。

## 4. 这次不做

拍照、写报道等玩法；NPC 打分行为系统（`docs/design_route_npc_behavior.md`）；进出楼的门；车辆行驶；昼夜。新动作（推门、上下台阶、推车、拄拐）等场景里有门、台阶再接。

## 附：正交和透视

`core/camera-params.json`（空地是 `scenes/empty_ground/camera-params.json`）的 `projection`：`perspective`（现在用的，视角 `fov`，缩放 = 改镜头离注视点的距离）或 `orthogonal`（缩放 = 改画面高度）。两种下 `tools/check_camera.gd` 都验过拖动、缩放、转动（测试点取在画面中心偏下，透视下画面上方的点可能落在场景外很远）。街上人群"拉远时隔几帧重建姿势"按镜头注视处的画面高度算，两种都适用。
