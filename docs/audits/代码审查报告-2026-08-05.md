## A. 前后一致性（代码 ↔ 文档 / 内部）

### A-1 🟡 PixiJS 版本文档过时
- `CLAUDE.md` 开头写 “PixiJS 5 原生”，但 [index.html:14](index.html#L14) 实际加载 `pixi.js@7.4.2`。
- 影响：新人/工具会按 v5 API 找文档，实际是 v7。建议把 CLAUDE.md 的 “PixiJS 5” 改为 “PixiJS 7”。

### A-2 🟡 `_spawnTrees` 注释与实现相反：注释说树不设 `_sortY`，实际设了
- [scenes/SceneInitializer.js:40-41](js/scenes/SceneInitializer.js#L40) 注释：“不设 `_sortY`（用默认 y 参与 Y 排序）”。
- 但 [entity/tree/tree.js:6](js/entity/tree/tree.js#L6) 的 footprint 返回 `sortDY: -e.height * 0.35`，而 [core/PropEntity.js:24](js/core/PropEntity.js#L24) `if (this.footprint.sortDY) this._sortY = this.y + this.footprint.sortDY;` —— 树**实际带了负的 `_sortY` 偏移**。
- 影响：注释误导。要么注释错、要么该偏移是遗留没清。需你确认树到底该不该有排序偏移（见 C-1 对遮挡效果的讨论）。

### A-3 🟡 `StreetScene` 顶部注释对 stall/tree 的排序描述与代码不符
- [scenes/StreetScene.js:10](js/scenes/StreetScene.js#L10) 注释：“stall/tree 用 `_sortY` 上移排序基准以遮挡后方 NPC”。
- 实测代码：
  - `stall` 的 `sortDY: 0`（[entity/stall/stall.js:6](js/entity/stall/stall.js#L6)）—— **根本不设 `_sortY`**。
  - `tree` 的 `sortDY` 为**负**（往“远”移），效果是让树排得更靠后、近处 NPC 走到树前，而不是“遮挡后方 NPC”。
  - 真正带**正** `sortDY` 的是 `sign`（+9，[entity/sign/sign.js:3](js/entity/sign/sign.js#L3)）。
- 三者关系与注释相反。EntityManager 是升序绘制（`_sortY` 小=先画=靠后，[core/EntityManager.js:106](js/core/EntityManager.js#L106)），负偏移=更靠后=更不遮挡后方。注释把 stall 也算进去且把方向说反了。

### A-4 🟡 CLAUDE.md 对 busstop barrel 的描述与实现不符
- CLAUDE.md（Entity 模式一节）：“`busstop-roof/bench/sign` 不进 barrel……这三种改在各自 `draw*.js` 里注册。”
- 实测：
  - `drawBusStopRoof.js`、`drawBusStopSign.js` **确实被 barrel import**（[entity/props.all.js:33-34](js/entity/props.all.js#L33)）—— 即“进了 barrel”。
  - `busstop-bench` 注册在 [entity/seat/seat.js:118](js/entity/seat/seat.js#L118)（**不是** `drawBusStopBench.js`），随 `seat.js` 进 barrel（[props.all.js:17](js/entity/props.all.js#L17)）。
  - 真正没进 barrel 的只有 `busstop.js` 本体（它 import `PropEntity`，会成环）。
- 结论：防环的判断没错，但“这三种不进 barrel / 在各自 draw 文件注册”的表述是错的。建议改为“`busstop.js` 本体不进 barrel；roof/sign 在各自 draw 文件注册并进 barrel，bench 在 seat.js 注册”。

## C. 遮挡（Y 排序）

### C-1 🟢 树的负 `sortDY` 效果需实测确认
- [entity/tree/tree.js:6](js/entity/tree/tree.js#L6) `sortDY: -e.height * 0.35` 把树排序基准上移（更靠后），意图应是“让路过的 NPC 走在树干前面”。这本身是合理的 2.5D 取舍，但与 A-2/A-3 的注释表述矛盾。建议：确认视觉效果 OK 后，把 A-2/A-3 两处注释订正，避免后人误改。

### C-2 🔴 坐→躺时 `_sortY` 遮挡翻转 —— 已确认为真实 bug
- [entity/seat/seat.js:72-73](js/entity/seat/seat.js#L72)：`sitDown` 用 `far = facing === 'up' || 'left'`，far 时设 `_sortY = bench.y - 1`（NPC 在椅**后**，被椅遮挡）。
- [entity/seat/seat.js:106](js/entity/seat/seat.js#L106)：`alignLie` **无视 facing**，一律 `_sortY = bench.y + 1`（NPC 在椅**前**）。
- **✅ 已与你确认：当前只有横向长椅（长轴沿 X = `facing 'up'/'down'`），且允许躺。** 其中 `facing:'up'`（靠里/远侧那排）命中 `far=true`：
  - 坐着 → `bench.y - 1`（椅后）
  - 躺下 → `bench.y + 1`（椅前）
  - → 同一张 up 朝向长椅上，NPC 从坐切到躺会**瞬间从椅后跳到椅前**，遮挡翻转。`sit_bench → lie_bench` 由 [NpcProfile.js:26](js/npc/NpcProfile.js#L26) 概率 0.03 触发，会真实发生。
  - （`facing:'down'` 两处都是 `bench.y + 1`，一致，无此问题。）
- **修法**：`alignLie` 复用 `sitDown` 的 far 判定 —— `const far = bench.facing === 'up' || bench.facing === 'left'; npc._sortY = far ? bench.y - 1 : bench.y + 1;`，让坐/躺同层，消除翻转。

### C-3 🟢 公交站顶棚单一 `_sortY`，棚内候车 NPC 可能被错误遮挡
- [entity/busstop/busstop.js:104](js/entity/busstop/busstop.js#L104) 顶棚用 `_sortY = pillarBottomY`（前柱落地点）作为整体排序键，但顶棚是跨纵深的结构（顶板在上、前后柱）。
- 站在棚内、`y < pillarBottomY` 的候车 NPC 会整体排在顶棚之前 → 有被顶板/前柱错误遮挡的风险。需实测两侧（far/near）公交站的候车观感确认。

### C-4 🟢 车辆纵向抖动直接进排序键，可能 z 序闪烁
- [entity/vehicle/VehicleEntity.js:49](js/entity/vehicle/VehicleEntity.js#L49) 每帧 `this.y = this._laneY + sin(...) * 3`，±3px 抖动的 `y` 直接用于 Y 排序（scale 用的是稳定的 `_laneY`，排序用的是抖动的 `y`）。
- 当车辆与临近同深度的 NPC/实体 `_sortY` 相差 <3px 时，可能出现每帧遮挡关系抖动。低频问题，登记备忘。

- [scenes/sceneFeatures.js:128](js/scenes/sceneFeatures.js#L128) `vehicles` 从 `layout.busStops` 建**行为**层 `BusStop` + `WaitForBusLayer` 候车区；
