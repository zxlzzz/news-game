## 四条核心说法

### 1. 普通内容只加一行

`rows` 以行为名为键；默认模板为 direct，显示名称默认取动作中文名。动作声明集中在 `actions`，once／hold 演示时间集中在 `defaults`。整理衣服、挠头、揉眼、看表、伸懒腰各自只占一行，不写准备、退出、恢复或结果回调。

候选身份为行为名与具体使用点 ID。设施字典中的每个 ID 每次只枚举一次，不产生重复绑定；正坐和瘫坐是两条行为。again 也按行为与目标共同记录，不会刚用过 A 就连 B 都禁用。

“看书”验收实际执行了一遍：测试先从完整表删除 read_book，保留动作、人物和工具声明，再只恢复以下一行，检查删除该行后其余表内容与原快照完全相同：

```json
"read_book":{"base":2,"use":"use_tool","tool":"book","action":"read_book"}
```

随后执行该行：坐着且拿手机的人先收手机、从包里取书、坐着看书，结束仍持书；没有书的人不产生候选。没有加模板代码、改其他行为或补人物偏好。这里的前提是 read_book 动作语义和该人物拥有的书本来已声明，未把新造物品算作行为新增的一部分。

### 2. 身体条件由共用准备处理

实际状态独立于事情：`held` 是实际物品 ID，`storage` 记录每个存放处接受的类别、容量与内容，`support` 记录座位 ID，`pos/place` 记录位置／使用点；物品有唯一位置，台面上放下的物品留在台面。

只读 preview 模拟有限的已声明准备：需要站立或移动时从座位起身；需要腾手时优先放入相容且有空位的随身存放处，否则放到当前可及且允许放置的支撑面；use_tool 检查工具已在手还是实际存放在本人身上，需要时取出。没有已定义方法就没有候选，不凭计时生成物品，也不搜寻任意取得工具的计划。

准备结束才同步提交物品位置或支撑变化，再重新判断下一步。take_tool 成功只完成准备。正常结束不预先收工具；以后选中的行为若需要空手，再处理自己的准备。

验证涵盖：持手机仍能选整理衣服；无存放处的包裹放到台面；无存放处也无台面时不可用；正坐结束仍占座；坐着仍能选站姿行为；读书不要求先站起来。执行中失去工具会由动作的继续条件停止；when 只作入口，入口条件后来消失本身不结束仍合法的动作。

### 3. 可中断，不等播放完

沿用旧选择器的基础分、个人标签系数、距离衰减、jitter、rethink、again 骨架。无当前事情时每种行为只抽一次扰动并跨其目标共享；有当前事情时挑战者无扰动，与事实重算的当前 U 加保留扰动比较。sight 只限制新发现，当前已绑定目标越界不立即归零，当前分不随时间衰减。基础分／个人系数为零不能被扰动复活，处境表多条命中取最高值。

高分选择确认后立即替换当前事情及动作实例，释放旧接近预留，不等待 once／hold／准备／移动结束。比较间隔仍为共享 rethink=0.5 秒，“随时”表示没有必须播完的保护段。正常完成或明确受阻才写共享冷却，单纯被替换不写成功或完成冷却。

动作持有实例 ID、进度与已提交标记；同一动作持续时不重置进度。效果提交前核对当前实例和实际条件，同步改变实际状态。验证逐一中断了普通 once、hold、起身、取工具、放物、坐下、走路，并直接尝试旧实例提交，确认旧实例不能再写效果。中断前已成立的状态不被重置，中断前尚未成立的取物／放物／坐姿效果不会伪造成立。

### 4. 两行文字

上行来自当前行为，下行来自当前动作；没有当前事情显示单行“暂无事情”，离开后不显示。三个模板中主要动作就是该事情的执行，因此主要动作合并为一行，包含“闲逛／走路”“离开／走向出口”等名称别称；准备动作另占下行。状态变化从执行器写入，不从文字反推。

测试验证普通主要动作、看书、闲逛别称合并为一行；真实场景加载时建立每人的 PanelContainer／Label，并在头顶投影位置刷新。没有进行窗口截图或肉眼排版验收。

## 同帧占位

实际身体占用与接近／准备预留分开保存，但新请求一律经同一个分配入口检查。位置资源与放物台面资源可以成组申请，整组可用才授予。

执行效果／外界身体事实先进入实际状态，随后只读生成各人的候选及工作预览。快照中已被其他人实际占用或预留的资源不可用；本帧同时发出的新需求先收集，再按有效分降序裁决。平分用固定 seed、稳定人物与候选身份决定，不依赖人物数组顺序。

所有首选处理完，再统一处理失败者各自最多一个后备。后备来自同一次缓存列表，必须仍严格超过缓存的有效当前分，不重抽扰动，并重新检查已更新的占用表。后备失败不再试第三个，保留仍有效的当前事情。确认新选择后才释放旧预留。已有事情后来需要的新准备资源也只能进入统一入口，推进函数不能现场抢位。

预留释放不删除身体事实：坐姿保持结束仍占座；看公告结束但人还站在使用点也继续阻挡他人。离开原点之后才解除该处实际位置占用。

验证包括：三人同帧争两个设施，一人首选成功、一人后备成功、第三人后备再次失败；倒转人物数组后各人结果相同；6 分首选争用失败后不能用 1.2 分行为替换仍有效的 3.5 分当前事情；已经结束的设施行为仍有实际身体占用；两人不能把两个包裹同时提交到只有一个空位的台面。

## 方案歧义与本批处理边界

- 主方案让 stand_up 覆盖“坐着／蹲着”，与 actions.md 的座位起身冲突。本批按任务及动作清单，只处理座位支撑；不做地面起身。坐下采用 behaviors.md 已写的 `sit_down → sit_bench/slouch_bench` 共用过渡，已坐在该座位时直接换保持，不重走、不重坐。
- 台面取物的 pick_up／take_item 冲突本批不走到：只实现放物，放下后不自动拿回，也没有实现地面捡物。
- 方案没有规定手位、存放处及台面数据格式。本批用一个“手持物件”槽，允许多个具名随身存放处；不模拟左右手各持一个物件。台面放物过程按整张台面互斥、容量按实际物品数检查，不做台面几何装箱。
- 本批的使用点是示意场景里明确声明的离散点；座位起身在该点原地将支撑改为地面，`rise_clear` 表达该座位允许起身，独占点同时保护该空间。不宣称验证了真实座椅几何、碰撞或身体接触，也不扩展起身规划。
- 闲逛用场景内三个地点作实际目标，离开用两个出口；仍用现有 WalkGrid 和 crowd 的按路程采样方式移动。网格路径末端是格心，本批像旧 crowd 的到站处理一样补到实际使用点的最后一步，并检查真的抵达，不能只靠演示时间当到位。没有新增寻路或人群避让机制。
- 当前枚举源只有自身行和设施字典，实际目标天然去重；未扩展伙伴、邀请、服务、电话等来源。没有实现 pair_once、service、电话、地面起身、拾物或 TODO 流程分支，停用项明确留在表中。once／hold 只有共享演示时长，效果在完成点提交，没有额外正常余段或恢复任务。
- “主要动作与事情同义”只按这三个模板的语义处理，不做自然语言同义词识别；后续若加入主要动作只是事情局部步骤的模板，须由该模板明确其显示语义，不能照搬本批合并规则。

本批验证的是文字执行、状态和选择约束；未将这些检查当作动画接触、素材时长、连续动作或画面布局已经验收的证明。
