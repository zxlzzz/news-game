# 动物动作 — 路线（草案）

## 当前动作供给约定

- 猫、狗和鸟同人体动作一样：每个名字只采样自己的动作。单次片段到末尾保持末姿，循环片段只循环自身，拖动时间可直接复现；动作库不预置走路或另一个动作。
- 鸟提供多个姿势、姿势之间的过渡，以及同样起止姿势但中间过程不同的变体。调用方选动作、管理根位置和朝向，依据实际速度、转弯与减速调整姿态；动作库不存世界飞行路线。接口和接续约定见 `../delivery/pigeon_motion_2026-10-02/library_report.md`。
- 街道行为选择、行走和动作打断属于调用方；空地独立片段播放不运行这套编排。源动作和运行时恢复分别检查，不以其中一个通过替代另一个。

## 0. 背景

- NPC 是火柴人，运行端在 Godot（`godot/`）；旧的 `js/` 已删除。
- 人的管线：每帧 3D 源关节 → 共用纯映射函数 + 参数 JSON → 要画的 3D 点 → 按当前朝向转、投影、按深度画。
- 动物要求（Hsinlung，2026-09-22）：**画成纯黑剪影**；和人一样用 3D 坐标实时转换，**能看出转向的 3D 感**。

## 1. 已经试过的

### 1.1 视频动捕（MoCapAnything V2，官方 HF Space）

- 用 `mocap_space.py` 直接调官方网页版（Gradio 队列接口），不用本机装环境。
- 参考骨架用的是 demo 自带的 Dog（Truebones，53 关节）。**结果只能本地预览，不进仓库。**
- 跑过两段：官方样例侧拍小跑（背景已抠）、维基共享资源的旧金山街拍黑色长毛狗（CC BY-SA 3.0）。
- 结论：
  - 姿势能读出来（腿交替、尾巴、低头），难的街拍素材也行。
  - `*_pose_pred.npy` 骨长不恒定（同一根骨头长度浮动 50%–90%），**要用 BVH 做正向运动学**才得到刚性骨架。
  - 输出是**原地踏步**（Hips 水平固定在原点），前进量要从着地脚反推。
  - 画成纯黑剪影后问题更明显：**脚会滑、常悬空**，着地判断不准（按高度判只有 4%–26% 帧着地）。
  - 放进游戏的用法（沿弯曲路线播放）时：速度固定，不会减速、不会停，转弯只能硬拧，脚滑更重。
- 限制：免费 ZeroGPU 额度约 5 分钟/天，每次预留 180 秒 → **一天只能跑一段**。

### 1.2 程序生成步态（`dog3d.template.html` 内）

- 每只脚是地面上的世界坐标：着地时钉死，抬脚时按身体速度预测落点、抛物线过去。
- 走（侧对步序 LH→LF→RH→RF，着地占比 0.64）与小跑（对角步，0.42），按速度自动切换，相位平滑过渡。
- 腿三段：两骨 IK（膝/肘弯向取固定方向）+ 末端固定方向的一节（掌/跖），抬脚时末端内收。
- 身体：肩带跟着航向走，髋带被拖着跟（弯道时身体自然弯）；头在转弯时先转向、停下时左右看；尾巴左右摆。
- 路线跟随：前视点转向、弯道减速、停靠点停 3 秒；停下时如果脚不在身体下方会补一两步再站定。
- 输出每帧就是 3D 点，和人的"3D 点 → 转向 → 投影 → 画"完全同一套。
- 结论：脚不滑，速度和转向都跟得上，纯黑剪影下观感干净。
