# 人体动作：怎么查、怎么改（给 ChatGPT，2026-10-01，Claude 写）

目的：让你自己把 239 个人体动作逐条查完、改好，而不是照一张清单改几处。下面是方法、工具、改动原则，以及 Claude 这次犯过的错。Claude 已改过一版（见 `../返工单.md`"人体动作"一节），那一版**只是起点**，要你按本文的方法重新逐条审核，不对就推翻。

## 1. 什么叫"对"

- **原始动作（npz）是唯一的依据。** 游戏里的最终画面，要让人一眼读出原动作想表达的事（挠头就是手在头顶，扫地就是扫帚在地上来回）。
- 火柴人比例（大头、短大臂、长小臂、没有肩宽和身体宽度）是 Hsinlung 定的画风，不能改。要做的是在这个比例下保住动作的**关系**：手碰头、手碰物件、双手相对位置、脚踩地、坐在座位上。
- **数值检查全部通过 ≠ 画面合格。** 七个 `check_*` 只查骨长、够得着、脚不穿地、能 seek，不查动作像不像原意。
- 验收靠 Hsinlung 看画面。你交付时说明"该看哪几条、看哪里"。

## 2. 一个动作经过的阶段（问题出在哪一段，就改哪一段）

| 阶段 | 位置 | 常见问题 |
|---|---|---|
| A. 原始骨架 | `assets/animations/npz/<id>/motion.npz`（77 关节） | 素材本身弱或错：没有器械时人站在地上、扫动太小、姿势错乱。只能重新生成，不要在后面硬掰 |
| B. 导出 | `scripts/export-npc-motion.py` → `godot/npc/motion/<id>.json`（16 关节） | 一般无损（误差 < 0.01 mm），循环接缝最多抹平 15 cm |
| C. 统一映射 | `godot/npc/skeleton_mapping.gd`（与 `sth/motion-study/skeleton-mapping.mjs` 逐行一致），规则在 `docs/design-plans/npc-skeleton-mapping.md` | 比例差异导致手放错位置、穿头，影响所有动作 |
| D. 播放 | `godot/npc/clip_pose.gd` | 去前进量、转向、脚底倾角 |
| E. 交互覆盖 | `godot/npc/interactions.json` + `interaction_player.gd` | `base` 换动作、手写的身体/脚/手轨迹盖掉原动作、配件位置写死 |
| F. 贴地 | `godot/npc/contact_pose.gd` | 脚、头穿地 |
| G. 配件、物件 | `godot/types/held_*.tscn`、物件类型、`clip-setup.json` | model 偏移被误拖、物件互相穿插、缺模型 |

**方法：每个动作都要并排看 A、C（无覆盖时）和最终画面，找出问题第一次出现在哪个阶段。** 不要只看最终画面就猜原因。

## 3. 工具（本目录 + `godot/tools/audit_dump.gd`）

1. **导出各阶段姿势**（在 `godot/` 下运行，headless，不改任何文件）：
   `godot --headless --path . -s res://tools/audit_dump.gd -- <dump.json> 24 [动作名…] [--patch=<json>]`
   - 每个动作在一个循环里取 24 个时刻；`pre` = 只映射后的姿势，`final` = 最终画面，`things` = 配件、物件的包围盒。
   - `--patch`：只在本次运行里替换 `interactions.json` 的条目（`{"动作名": 新配置或 null}`）。**改正式文件前先用它试**。
2. **出对比图**：`python ov2.py <dump.json> <输出目录> [动作名…]`。每行一个动作，4 个时刻 ×（原始骨架绿色 | 映射 | 最终），右边三张是侧面。
   - 依赖 `audit.py`（Python 版映射和 77 关节原始骨架）、`sheets.py`。
   - 运行前把 `audit.py` 开头的路径改成本机路径。
   - `audit.py` 的 `Mapper` 是**改前**的映射（第 9 步之前），只用来对比"旧映射"。新映射以 Godot 导出的 `pre` 为准。
3. **手轨迹改动量**：`python handtracks.py`（读 `dump.json`）。列出每条手轨迹把手挪了多远、在什么坐标空间、有没有 `window`。
4. **逐帧跳动**：`node jumps.mjs`。比较新旧映射每帧手、肘的最大位移，找出"开关式"跳变。运行前先 `git show HEAD:sth/motion-study/skeleton-mapping.mjs > old-mapping.mjs`。
5. **真实截图**（窗口运行）：`godot --path . res://scenes/empty_ground/level.tscn -- --entry <动作名> --time <秒> --look 0 0 --size 4 [--yaw 140] --shot <png>`
   - 不给 `--look/--size` 时自动取景常把头切掉。
   - 有物件挡住时用 `--yaw` 转到另一面。
   - 线框图看不出描线、遮挡、配件朝向，**最后一定要看真实截图**。

## 4. 逐条检查清单（每个动作都要过）

1. 原始骨架在干什么？用一句话写下来（如"右手在头顶挠"）。原始骨架本身对不对：有没有器械缺失、姿势错乱？
2. 映射后（`pre`）这句话还成立吗？重点看手和头的关系、手和身体的关系、双手的距离、坐姿胯的高度。
3. 最终画面这句话还成立吗？比映射后多了什么改动、少了什么动作？
4. 配件：在手里的位置和朝向对吗（工具头朝下、杯口朝上）？有没有悬空、穿模、被物件挡住？
5. 物件：人站的距离对吗？手碰的是物件上真实的点吗？物件有没有被别的东西挡住或穿进去？
6. 动起来：有没有相邻帧跳变、滑步、动作节奏和原动作对不上？至少看一遍连续播放。
7. 两人动作：两人的手是否真的对上，时间是否同步。

## 5. 改动原则（Hsinlung 的规矩 + 这次查出来的）

- **能用原动作就用原动作。** `base`（换成别的动作再手写轨迹）只在原素材确实没有器械、用不了时才用，而且要逐条看过原素材再下结论。
- **手轨迹只用于真接触。** 碰物件、碰另一人的那一段用 `window` 渐入渐出，可以给多段。只摆姿势的手轨迹一律删掉。
- **配件跟手走，不是手追配件。** 位置信息写在不动的一方：配件在手里的偏移写在 `types/held_*.tscn` 的 `model`；双手工具用 `item.align`；要触地的工具用 `ground` 加 `slide`。
- **人离物件远时用 `shift` 把人挪近**，不要去改物件的 `post_*` 标记，那是多个动作共用的。
- **坐姿要对座位高度时**，`body.hip` 只给位置、不给 `direction`，保留原动作的身体倾斜。
- **改映射时，站姿必须完全不变。** 用 `stand_idle` 第 0 帧标定。验证：新旧映射对 `stand_idle` 的手、肘差应为 0。
- **不要按比例缩放手的左右、前后位置。** 火柴人没有身体宽度，按比例缩放会把叉腰、插兜的手推离身体。只有高度可以按身体部位分段对应。
- **每帧计算里不要有开关式切换**（"超过某值就换一种算法"），要按程度平滑过渡，然后用 `jumps.mjs` 量跳变。
- **两骨 IK 在胳膊接近伸直时，弯向会来回翻**，要加稳定项：原始骨架自己的肘弯方向。
- 数据错了就报错退出，不兜底；数值放 JSON，不写死在代码里。
- 改了 `skeleton_mapping.gd` 必须同步改 `.mjs`，重跑 `node tools/make_mapping_reference.mjs --mapping ../sth/motion-study/skeleton-mapping.mjs`，`check_mapping` 要通过。

## 6. Claude 这次犯的错（别再犯）

1. 把"查"做成了"改"。你的任务里，查和改都由你来做；拿不准的列出来问 Hsinlung。
2. 扫帚、拖把的 `align` 方向填反，工具头朝上；线框图看不出，真实截图才发现。**配件朝向必须看截图。**
3. 第一版映射按比例缩放手的全部坐标，结果叉腰、插兜、抱臂都变差了。**每改一次映射，要回看"贴身动作"**：`hands_on_hips`、`walk_hands_pockets`、`cross_arms`、`sit_bench`。
4. "手臂穿头就退回旧规则"用了开关，`photo_overhead` 每帧跳 19 cm。改成平滑过渡后降到 8 cm。
5. 只用 4 帧粗筛就下结论。粗筛只能找候选，结论要用 24 帧、两个视角，加连续播放。
