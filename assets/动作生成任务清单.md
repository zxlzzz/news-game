## 执行约定

- 每个动作是独立的完整单人 NPZ，不依赖旧 overlay、旧骨架、游戏状态机或动画注册方式。
- 输出位置：`animations/npz/<英文动作名>/motion.npz`；同目录保存 `meta.json`。目录不带 seed、版本号；确实保留多个并列版本时才在名字末尾加 `1`、`2` 等。
- `[x]` 表示已有选中素材，`[ ]` 表示未完成。标题中的“待重评／待条件／范围外”不是可以直接执行的普通队列。
- 串行生成，每条生成后先检查画面或运动数据，再决定保留、微调或暂缓。提示词和时长按动作组织，不直接翻译中文后套默认时长。
- 只保留选中结果。反复尝试仍不明确的动作记录原因，停止盲目换词，不为勾选清单而交付不合格素材。
- 正面／侧面等旧二维绘制版本合并成一个三维动作；真正不同的姿势或运动内容仍独立列项。不会假定站姿动作能自动合成坐姿动作。
- 新循环遵循供给路线 §5：首尾同姿势，根水平位移保留；首尾重复帧只播一次。六条新循环已登记 `animations/clip_endpoints.json`，已有 63 条不重做。端点一致不代表速度严格连续；不同年龄仅记录动作风格，不据此宣称不同年龄的骨架。
- **默认顺序：已完成项跳过 → A → B → C → D → E。** F 先验证物件定位条件；G、H 只登记范围，未经后续明确授权不执行。点头／摇头列入待重评，不能每批都无条件重试。

## H. 群体编排与情境标签（不是单条动作文件任务）

这些内容来自工作稿，保留以免遗漏，但需要场景中的多角色位置和行为调度。完成基础 NPZ 不等于完成这些行为；本轮不修改运行时。

- [ ] 排队／排队站：复用自然站立，队列间距由场景处理。
- [ ] 排队不耐烦：组合看表、抖腿、探看、看手机等已选动作。
- [ ] 插队／侧身挤看：需要人群路径与空间条件；探看身体动作另见 B。
- [ ] 凑近／散开／一哄而散：需要多角色路径；单人走跑另见 D。
- [ ] 被吸引走来：转头、减速、拐向焦点的情境组合。
- [ ] 围观／聚集／追逐：基础站、走、跑与共同焦点编排。
- [ ] 对指／摊手对峙／叉腰对峙：单人指示、摊手、叉腰完成后仍需双方编排。
- [ ] 广场舞同步／快闪：个体舞步与群体同步分开验收。
- [ ] 小孩赖地：使用坐地／蹲姿表达的情境；不因年龄标签复制一个成人 NPZ 冒充儿童骨架。
